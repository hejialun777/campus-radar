# 校园活动雷达

把散落在通知、群聊、海报里的校园活动、竞赛、招募和同学自发信息，
整理成一句「我现在该做什么」。

纯静态前端，不依赖后端、数据库和构建工具，打开就能用。

> 页面中的所有活动、通知与招募信息均为**演示用模拟数据**（26 条，时间背景为 2026 年 9 月 19 日），
> 不代表任何学校的真实通知。

**在线访问**：https://hejialun777.github.io/campus-radar/

## 运行方式

### 本地运行

```bash
node serve.js          # 默认 8080 端口，可跟端口号，如 node serve.js 8090
```

终端会打印本机和局域网地址：

```
本机：   http://localhost:8080
局域网： http://192.168.x.x:8080
```

局域网地址可以直接在手机上打开，方便按真实使用场景体验。

也可以直接双击 `index.html`（个别浏览器对 `file://` 下的剪贴板、日历下载有限制，
完整体验建议用上面的方式）。

### 线上部署

仓库启用 GitHub Pages 后，把发布源设为 `main` 分支根目录即可，
访问 `https://<用户名>.github.io/<仓库名>/`。

### 环境要求

- 任意现代浏览器（Chrome / Edge / Safari / Firefox）
- 起本地服务器需要 Node.js（`serve.js` 是约 60 行零依赖的静态服务器，作品本身不依赖它）

## 功能一览

### 搜索（首页）

- 搜索框独立成页，支持**中文输入**（输入法组合期间不重绘界面）；
- 匹配范围覆盖标题、**发布正文**、发布者姓名与单位、门类名称、地点、标签、原文；
- 可按 **A—F 六个门类** 和 **发布者身份** 筛选；
- 结果按状态分组（今天 / 快截止 / 还能报名 / 已截止可候补 / 长期开放 / 已结束）；
- 所有内容都在这里，**包括用账号发布的内容**。

### 门类 A—F

| 代码 | 门类 | 代码 | 门类 |
| --- | --- | --- | --- |
| A | 竞赛与训练营 | D | 志愿服务与观摩 |
| B | 招募与组队 | E | 学习资源 |
| C | 讲座与分享会 | F | 学生个人发起 |

### 距截止还剩 3 天

按当天日期算，把 3 天内截止的事项单独列成倒计时（还剩几小时 / 几天，越少颜色越重），
3—7 天的另折叠一层。已过期的、以及没给出具体时间的截止不进倒计时，
但仍会在卡片上如实标注。

### 发布者身份

学校 / 学院 / 老师 / 同学自主发布，四选一。注册时选定并填写学院（内置 18 个学院），
发布的内容挂在这个身份下，卡片上直接显示是谁发的、有没有确认过身份。

数据里没写明发布方的信息，单列一档「发布方未注明」，不替数据认领身份。

### 发布内容

必填三项：**门类、发布内容、截止时间**，缺一项发不出去。
补充信息（时间、地点、费用、联系方式）选填，但没填的会被如实记下来并提示同学去确认。
发布前需勾选「我确认以上内容由本人发布且信息属实」。

### 报名与报名名单

- 其他同学在活动详情里填**姓名 + 手机号**报名（需登录）；
- **发布者在「我的」里能看到报名名单**：谁报的名、手机号、学院、什么时候报的；
- 支持一键复制名单、移除某条报名；报名者可以自己取消报名。

### 「我要参加」必须留下姓名和联系电话

点 🎯 不是简单打个勾，而是弹出登记表单，**参与姓名和联系电话都是必填**（电话做 11 位校验）。
理由：不填联系方式的"参加"等于空报名——组织者找不到人，真到现场谁也没来。

已登记过的再点就是修改 / 取消；「我的 → 我参与的」里直接显示自己的姓名和电话。

> 旧版本存的是纯 id 数组（`["01","03"]`），打开时会自动迁移成带信息的记录，
> 迁移过来的旧记录会显示"还没填姓名和电话 · 去补填"，不会丢。

### 风险项目：报名 / 收藏 / 参加之前先弹提醒

系统识别出的风险项目（数据里标注的，或内容命中审核规则的），在用户点击
**收藏、我要参加、报名** 时都会先弹一层提醒，讲清楚：

- 系统识别到了什么问题（具体原因 + 该怎么防范）
- 这条信息的基本情况：发布者身份、发布方、信息完整度
- 高风险用"我已了解风险，仍要继续"，低风险用"知道了，继续"，措辞分级

报名时填好的表单内容会先暂存，用户确认风险后直接落库，**不用重填一遍**。

风险提示里明确写了「只代表这条信息有疑点，不代表已经确认有问题」——
提醒的目的是让人多看一眼，不是替人下判断。

### 「我的」：三个分类 + 左侧项目栏

「我的」按 **我的收藏 / 我参与的 / 我发布的** 分成三栏，桌面端是左侧竖排导航，
手机端是顶部横向标签，点击即跳转到对应分类。三栏各自独立，**同一条内容可以同时出现在多个分类里**
（比如自己发的又收藏了）。

「我参与的」= 标记了「我要参加」的 + 报名过的。自己发的内容不会自动算成「参与」。

### 内容审核

用户发布前，标题、正文、联系方式会先过一遍规则库，命中就**不允许发布**，
并逐条列出：哪一栏、命中了哪个词、属于哪一类、为什么不行。改完才能提交。

覆盖 8 类：

| | 类别 | 例子 |
| --- | --- | --- |
| 📢 | 虚假与夸大宣传 | 全校第一、史上最强、100% 包过、错过再无 |
| 💊 | 医疗健康 | 根治、药到病除、无副作用 |
| 💰 | 金融 | 稳赚不赔、零风险、内幕消息 |
| 🚪 | 诱导与引流 | 加微信、扫码进群、绕过平台 |
| 🔮 | 迷信玄学 | 算命、改运、开光 |
| 🚫 | 低俗擦边 | 软色情与低俗谐音 |
| ⚠️ | 暴力与涉恐 | 一票否决类 |
| 🛡️ | 校园安全风险 | 零门槛日结、刷单返利、代写论文 |

**关于误伤**：规则刻意避开了「裸词匹配」。校园场景里「第一教学楼」「最好提前到场」
「微信号：abc123」「唯一报名入口」都是正常表述，如果直接匹配「第一」「最好」「唯一」，
这些内容会全部被拦。所以规则按**组合词**写（「全校第一」「最低价」「唯一入口」），
宁可漏一点，也不要大面积误伤正常内容。测试里有 10 条正常表述专门验证不被误拦。

### 其它

后续通知自动合并、按「现在」推算状态、新生模式、信息完整度、
搜索关键词高亮、一键加入手机日历（.ics）、复制信息到群里。

## 已知边界

- **数据是本地模拟的**。搜索、发布、报名、账号都基于浏览器 `localStorage`，
  **不跨设备同步**：换设备、换浏览器、清缓存数据就没了。
- **登录不是真实身份认证**。纯静态页面没有服务端，账号只存在本机，
  身份是自选的（谁都能注册成「计算机学院」）。密码用「每账号独立随机盐 + SHA-256」存储，
  在不安全上下文（如 `file://`）下会退回非加密散列。
  界面上和这里都写清楚了，没有假装它安全。
- **报名数据同样不跨设备**。发布者能看到报名名单，前提是报名发生在同一台设备上。
  真实多设备场景需要后端。
- 26 条演示数据的时间背景固定为 2026 年 9 月 19 日。页面默认跟随真实时间推算状态；
  如果打开时间离这个日期较远，可在「我的 → 设置」里把时间基准锁定到 9 月 19 日 14:00。
