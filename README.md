## 运行方式

### 线上访问（推荐）

仓库启用 GitHub Pages 后，直接访问：

```
https://<用户名>.github.io/<仓库名>/
```

各子项目在 `https://<用户名>.github.io/<仓库名>/projects/<项目名>/`。

### 本地运行

项目是纯静态页面，不依赖后端和数据库。二选一：

**方式一：直接用浏览器打开**

双击根目录的 `index.html` 即可。（个别浏览器对 `file://` 协议下的剪贴板、
日历下载有限制，功能体验建议用方式二。）

**方式二：起一个本地服务器**

```bash
node serve.js          # 默认 8080 端口，可跟端口号，如 node serve.js 8090
```

终端会打印本机和局域网地址：

```
本机：   http://localhost:8080
局域网： http://192.168.x.x:8080
```

局域网地址可以直接在手机上打开，方便按真实使用场景体验。

> `serve.js` 只是为了本地预览方便，约 60 行纯 Node 代码、零依赖。
> 作品本身不依赖它。

### 环境要求

- 任意现代浏览器（Chrome / Edge / Safari / Firefox）
- 方式二需要 Node.js（仅用于起静态服务）

## 关于"多个项目"

首页完全由 [`js/projects.js`](js/projects.js) 这个数组驱动。新增一个项目只需要：

1. 在 `projects/` 下新建目录，放好 `index.html`；
2. 在 `js/projects.js` 里加一条记录。

首页会自动多出一张卡片，`index.html` 不需要改动。目前材料中只有第四部分提供了
可直接使用的数据集，因此先完成这一个项目。

## 已知边界

- 数据来自考核题目的模拟材料，**时间背景固定为 2026 年 9 月 19 日**。
  页面默认跟随真实时间推算状态；如果打开时间离这个日期较远，
  可在「我的 → 设置」里把时间基准锁定到 9 月 19 日 14:00。
- 收藏、已报名标记和用户发布的内容存在浏览器 `localStorage` 里，
  换设备或换浏览器不会同步，清空浏览器数据会丢失。
- 用户发布的内容是本地模拟，没有真实的服务端审核。产品上的处理方式是
  在发布时做完整度自检、发布后标注「学生发布 · 未核实」并附风险提示。
